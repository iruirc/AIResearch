## Подробное описание запросов

### Q1: Лексическое vs семантическое сходство

**Запрос:** Какой Python фреймворк лучше использовать для REST API?

| Параметр | Значение |
|----------|----------|
| Сценарий | `lexical-vs-semantic` |
| Ожидаемый документ | Python Frameworks |
| Ключевые слова | FastAPI, API |

**Объяснение:** Bi-encoder может вернуть python-datascience (много упоминаний Python). Cross-encoder понимает связь REST API + framework и вернёт FastAPI.

**Ловушка для Ranking:** python-datascience содержит больше упоминаний Python

---

### Q2: Понимание негативного контекста

**Запрос:** У меня стартап из 3 разработчиков. Стоит ли использовать микросервисы?

| Параметр | Значение |
|----------|----------|
| Сценарий | `negative-context` |
| Ожидаемый документ | Когда НЕ использовать микросервисы |
| Ключевые слова | небольших команд, до 5 человек, стартапов |

**Объяснение:** Cross-encoder понимает, что 3 разработчика = небольшая команда, и находит документ про ограничения.

**Ловушка для Ranking:** microservices-benefits содержит больше ключевых слов про микросервисы

## Метрики оценки

| Метрика | Описание |
|---------|----------|
| **MRR** | Mean Reciprocal Rank — позиция правильного документа |
| **Precision@1** | Правильный ли первый результат |
| **Precision@3** | Сколько правильных в топ-3 |
| **NDCG@5** | Normalized Discounted Cumulative Gain для топ-5 |

---

## Как проводить тестирование

1. Загрузить все документы из папки `documents/` в RAG
2. Для каждого запроса выполнить поиск с `topK=5`, `minScore=0.5`
3. Записать позицию ожидаемого документа в результатах
4. Повторить с включённым reranking
5. Сравнить метрики MRR и Precision@1
