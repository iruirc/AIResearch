# Тестирование разницы между Ranking и Reranking в RAG

## Вопрос

> Можешь ли подобрать мне набор информации, которую можно использовать, чтобы более наглядно увидеть разницу между запросами к RAG с ранкингом и реранкингом. Какие вопросы при этом задавать?

---

## Ответ

### Ключевые сценарии для демонстрации

#### 1. Лексическое сходство vs Семантическая релевантность

**Проблема:** Bi-encoder (embedding) находит документы с похожими словами, но не обязательно релевантные по смыслу.

**Пример:**
- Запрос: "Какой Python фреймворк лучше использовать для REST API?"
- Bi-encoder может вернуть документ про "Python в Data Science" (много упоминаний Python)
- Cross-encoder вернёт FastAPI (точно понимает связь "REST API" + "framework")

#### 2. Негативный контекст

**Проблема:** Bi-encoder плохо понимает отрицания и ограничения.

**Пример:**
- Запрос: "У меня стартап из 3 разработчиков. Стоит ли использовать микросервисы?"
- Bi-encoder: вернёт "Преимущества микросервисов" (больше ключевых слов)
- Cross-encoder: вернёт "Когда НЕ использовать микросервисы" (понимает контекст "3 разработчика" → "небольшая команда")

#### 3. Многозначность терминов (Disambiguation)

**Проблема:** Bi-encoder не различает контекст использования омонимов.

**Пример:**
- Запрос "Расскажи про последние новости Apple" → Ожидается про компанию
- Запрос "Сколько калорий в Apple?" → Ожидается про фрукт
- Bi-encoder даст похожие scores для обоих документов
- Cross-encoder различит контекст по окружающим словам

#### 4. Сложные многошаговые запросы

**Проблема:** Bi-encoder не улавливает связь между несколькими концепциями в запросе.

**Пример:**
- Запрос: "Мы используем MySQL и хотим перейти на PostgreSQL. Какие проблемы могут возникнуть?"
- Bi-encoder: вернёт общий документ "Базы данных" (упоминает PostgreSQL чаще)
- Cross-encoder: вернёт "Миграция данных" (понимает связь "MySQL → PostgreSQL" + "проблемы")

## Метрики для сравнения

```
┌─────────────────────────────────────────────┐
│ 1. MRR (Mean Reciprocal Rank)               │
│    - Позиция правильного ответа в топе      │
│                                             │
│ 2. Precision@K                              │
│    - Сколько релевантных в топ-K            │
│                                             │
│ 3. NDCG (Normalized Discounted Cumulative   │
│    Gain) - учитывает порядок результатов    │
│                                             │
│ 4. Human evaluation                         │
│    - Ручная оценка релевантности 1-5        │
└─────────────────────────────────────────────┘
```

## Почему Cross-Encoder лучше для Reranking?

| Аспект | Bi-Encoder (Ranking) | Cross-Encoder (Reranking) |
|--------|---------------------|---------------------------|
| **Архитектура** | Отдельные embeddings для query и document | Совместная обработка query + document |
| **Скорость** | Быстрый (предвычисленные embeddings) | Медленный (вычисление на лету) |
| **Качество** | Хорошее для первичного поиска | Высокое для точного ранжирования |
| **Понимание контекста** | Ограниченное | Глубокое |
| **Применение** | Первый этап: отбор кандидатов | Второй этап: точное ранжирование |

        │
        ▼

        │
        ▼
   Top-5 результатов
