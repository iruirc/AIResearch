# RAG Preview и Debug Mode

## Обзор

Реализованы две функции для сравнения результатов RAG-поиска с реранкингом и без него:

1. **Preview Panel** - предпросмотр контекста ПЕРЕД отправкой сообщения
2. **Debug Mode** - отображение информации о контексте ПОСЛЕ получения ответа

---

## 1. Preview Panel (Предпросмотр контекста)

### Что это?
Модальное окно, которое показывает какие чанки будут использованы для RAG-контекста, позволяя сравнить результаты с реранкингом и без него.

### Как использовать?

1. **Введите вопрос** в поле ввода сообщения
2. **Нажмите кнопку "глаз"** (👁) рядом с кнопкой отправки
3. Откроется модальное окно с двумя колонками:

```
┌─────────────────────────────────────────────────────────┐
│  Предпросмотр RAG контекста                       ✕     │
├─────────────────────────────────────────────────────────┤
│  Запрос: "Как работает X?"                              │
├───────────────────────────┬─────────────────────────────┤
│  Без реранкинга (5)       │  С реранкингом (3)          │
├───────────────────────────┼─────────────────────────────┤
│  1. doc.pdf  [89.1%]      │  1. doc.pdf  [92.0%]        │
│     "Текст чанка..."      │     "Текст чанка..."        │
│                           │                             │
│  2. api.txt  [87.5%]      │  2. api.txt  [88.5%]        │
│     "Текст чанка..."      │     "Текст чанка..."        │
│                           │                             │
│  ─── Отфильтровано: ───   │  3. guide.md [85.0%]        │
│  3. old.pdf  [85.0%] ✗    │     "Текст чанка..."        │
│                           │                             │
├───────────────────────────┴─────────────────────────────┤
│  Стратегия: Cross-Encoder │ Отфильтровано: 2 │ 45мс     │
├─────────────────────────────────────────────────────────┤
│         [Отправить без реранкинга]  [Отправить с ✓]     │
└─────────────────────────────────────────────────────────┘
```

### Что показывается?

**Левая колонка (Без реранкинга):**
- Результаты первого этапа поиска (векторный поиск)
- Все чанки, прошедшие минимальный порог косинусного сходства

**Правая колонка (С реранкингом):**
- Результаты после применения стратегии реранкинга
- Только чанки, прошедшие дополнительную фильтрацию

**Статистика:**
- Стратегия реранкинга (Score Threshold / Statistical / Cross-Encoder)
- Количество отфильтрованных чанков
- Время обработки

### Кнопки действий:
- **"Отправить без реранкинга"** - отправит сообщение, игнорируя настройки реранкинга
- **"Отправить с реранкингом"** - отправит сообщение с использованием реранкинга

## 2. Debug Mode (Режим отладки)

### Что это?
Режим, при котором каждый ответ ассистента содержит информацию о том, какие RAG-чанки были использованы для генерации ответа.

### Как включить?

1. Откройте **RAG модал** (кнопка "RAG" в sidebar)
2. Перейдите на вкладку **"Настройки поиска"**
3. Прокрутите вниз до секции **"Отладка"**
4. Включите переключатель **"Режим отладки RAG"**
5. Нажмите **"Сохранить"**

### Как выглядит?

После включения, под каждым ответом ассистента появится сворачиваемый блок:

```
┌─────────────────────────────────────────────────────────┐
│ 🤖 Ответ ассистента...                                  │
│                                                         │
│ Lorem ipsum dolor sit amet, consectetur adipiscing...   │
│                                                         │
│ ▶ RAG контекст (3 чанков)                               │
└─────────────────────────────────────────────────────────┘
```

При клике на заголовок блок раскрывается:

```
┌─────────────────────────────────────────────────────────┐
│ ▼ RAG контекст (3 чанков)                               │
├─────────────────────────────────────────────────────────┤
│ Реранкинг: Cross-Encoder │ Отфильтровано: 2 │ 45мс     │
│ Токены: ~1200                                           │
├─────────────────────────────────────────────────────────┤
│ ┌─ doc.pdf ────────────────────────────── 92.0% ✓ ─┐   │
│ │ Текст чанка, который был использован...          │   │
│ └──────────────────────────────────────────────────┘   │
│                                                         │
│ ┌─ api.txt ────────────────────────────── 88.5% ✓ ─┐   │
│ │ Текст чанка, который был использован...          │   │
│ └──────────────────────────────────────────────────┘   │
│                                                         │
│ ┌─ old.pdf ────────────────────────────── 65.0% ✗ ─┐   │
│ │ Текст чанка, который был ОТФИЛЬТРОВАН...         │   │
│ └──────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────┘
```

### Что показывается?

**Сводка:**
- Стратегия реранкинга (или "Отключен")
- Количество отфильтрованных чанков
- Время обработки RAG-поиска
- Примерное количество токенов в контексте

**Использованные чанки (✓):**
- Название документа
- Скор релевантности (%)
- Фрагмент текста чанка

**Отфильтрованные чанки (✗):**
- Показаны серым цветом
- Чанки, не прошедшие порог реранкинга

## Сравнение подходов

| Характеристика | Preview Panel | Debug Mode |
|---------------|---------------|------------|
| **Когда видно** | До отправки | После ответа |
| **Цель** | Выбрать использовать ли реранкинг | Понять какой контекст использован |
| **Включается** | Кнопка 👁 | Toggle в настройках |
| **Сравнение** | Да, две колонки | Нет, только финальный результат |

## API Endpoints

### Preview контекста
```http
POST /rag/preview
Content-Type: application/json

{
  "query": "Ваш вопрос"
}
```

**Ответ:**
```json
{
  "query": "Ваш вопрос",
  "withoutReranking": [...],
  "withReranking": [...],
  "filteredResults": [...],
  "rerankingEnabled": true,
  "rerankingStrategy": "CROSS_ENCODER",
  "statistics": {
    "originalCount": 5,
    "finalCount": 3,
    "filteredCount": 2,
    "processingTimeMs": 45
  }
}
```

### Chat с Debug Info
При включенном `debugMode` в RAGSearchPreferences, ответ `/chat` содержит:

```json
{
  "response": "Ответ ассистента...",
  "sessionId": "...",
  "ragDebugInfo": {
    "query": "Вопрос пользователя",
    "usedResults": [...],
    "filteredResults": [...],
    "rerankingEnabled": true,
    "rerankingStrategy": "CROSS_ENCODER",
    "processingTimeMs": 45,
    "estimatedTokens": 1200
  }
}
```

## FAQ

### В чём разница между кнопками "Отправить без реранкинга" и "Отправить с реранкингом"?

#### Без реранкинга (`useReranking=false`)

- Используется только векторный поиск (cosine similarity)
- Все чанки с score ≥ minScore включаются в контекст
- ⚡ **Быстро** — мгновенный результат
- Может включить менее релевантные результаты

#### С реранкингом (`useReranking=true`)

- **Двухэтапный поиск:**
  1. Векторный поиск (как выше)
  2. Cross-Encoder (LLM) пересчитывает релевантность
- Отфильтровывает "шумные" результаты
- 🐢 **Медленнее** — может занять ~10-15 секунд
- Обычно более качественный контекст

#### Когда разница будет заметна?

Если поиск найдёт **5-10 чанков** с разной релевантностью (70%, 75%, 80%...), реранкинг:
- Пересортирует их по реальной релевантности к запросу
- Отфильтрует те, что "попали случайно"
- Оставит только действительно полезные

**Примечание:** Если найден только 1-2 чанка, разницы не будет — реранкингу нечего фильтровать/сортировать.

#### Практическое применение

Кнопки позволяют **переопределить глобальную настройку реранкинга** для конкретного сообщения — протестировать, какой вариант даст лучший ответ от AI.
