# DevOps и CI/CD

## Что такое DevOps

DevOps — это культура и набор практик, объединяющих разработку (Development) и операции (Operations). Цель DevOps — сократить цикл разработки, повысить частоту релизов и улучшить качество программного обеспечения.

## Основные принципы DevOps

### Культура сотрудничества
Разрушение стены между разработчиками и операционной командой. Общая ответственность за продукт от кода до продакшена.

### Автоматизация
Автоматизация всего, что можно автоматизировать: сборка, тестирование, развёртывание, мониторинг.

### Непрерывное улучшение
Постоянный анализ процессов и метрик, поиск узких мест и их устранение.

### Измерение
Принятие решений на основе данных. Метрики производительности, качества, скорости доставки.

## CI/CD Pipeline

### Continuous Integration (CI)

CI — это практика частой интеграции изменений в общую ветку. Каждая интеграция автоматически проверяется сборкой и тестами.

**Этапы CI:**

1. **Commit**: Разработчик отправляет код в репозиторий
2. **Build**: Автоматическая сборка проекта
3. **Test**: Запуск автоматических тестов
4. **Report**: Уведомление о результатах

**Преимущества CI:**
- Раннее обнаружение ошибок
- Уменьшение конфликтов слияния
- Постоянно работающая main-ветка
- Быстрая обратная связь

### Continuous Delivery (CD)

CD — это практика поддержания кода в состоянии, готовом к развёртыванию в любой момент.

**Этапы CD:**
1. CI Pipeline (сборка, тесты)
2. **Staging Deploy**: Развёртывание на staging-среду
3. **Integration Tests**: End-to-end тесты
4. **Ready for Production**: Код готов к релизу

### Continuous Deployment

Автоматическое развёртывание каждого успешного изменения в production без ручного вмешательства.

**Требования:**
- Высокое покрытие тестами
- Feature flags для управления функциями
- Мониторинг и автоматический откат
- Уверенность команды в процессе

## Инструменты CI/CD

### GitHub Actions

Встроенный CI/CD для GitHub. YAML-конфигурация, богатый маркетплейс actions.

**Пример workflow:**
```yaml
name: CI
on: [push, pull_request]
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - name: Build
        run: ./gradlew build
      - name: Test
        run: ./gradlew test
```

### GitLab CI/CD

Полноценная DevOps-платформа с встроенным CI/CD. Мощная система переменных и environments.

### Jenkins

Самый гибкий CI/CD сервер с открытым кодом. Тысячи плагинов, но требует администрирования.

### CircleCI

Облачный CI/CD с отличной интеграцией с GitHub. Быстрая настройка, параллельное выполнение.

### ArgoCD

GitOps-инструмент для Kubernetes. Синхронизирует состояние кластера с Git-репозиторием.

## Практики CI/CD

### Trunk-based Development
Работа в короткоживущих feature-ветках с частым слиянием в main. Избегание долгоживущих веток.

### Feature Flags
Включение/выключение функций без деплоя. Позволяет отделить деплой от релиза.

```python
if feature_flags.is_enabled("new_checkout"):
    new_checkout_flow()
else:
    old_checkout_flow()
```

### Blue-Green Deployment
Две идентичные среды (blue и green). Новая версия развёртывается на неактивной среде, затем трафик переключается.

### Canary Deployment
Постепенный выкат новой версии. Сначала 1% трафика, затем 10%, 50%, 100%. При проблемах — откат.

### Rolling Deployment
Последовательное обновление инстансов по одному. Нет простоя, но версии смешаны во время деплоя.

## Infrastructure as Code (IaC)

### Terraform
Декларативное описание инфраструктуры. Поддерживает множество облачных провайдеров.

```hcl
resource "aws_instance" "web" {
  ami           = "ami-12345"
  instance_type = "t3.micro"
  tags = {
    Name = "WebServer"
  }
}
```

### Ansible
Конфигурация серверов через YAML-playbooks. Agentless — работает через SSH.

### Pulumi
IaC на обычных языках программирования (TypeScript, Python, Go).

## Мониторинг и Observability

### Три столпа наблюдаемости:

**Логи:**
Структурированные записи событий. Централизованный сбор через ELK, Loki, CloudWatch.

**Метрики:**
Числовые измерения: CPU, память, latency, error rate. Prometheus + Grafana.

**Трейсы:**
Путь запроса через систему. Jaeger, Zipkin для распределённых систем.

### SRE метрики (SLI/SLO/SLA)

- **SLI (Service Level Indicator)**: Измеримая метрика (latency p99, availability %)
- **SLO (Service Level Objective)**: Целевое значение SLI (99.9% availability)
- **SLA (Service Level Agreement)**: Контракт с последствиями нарушения

## GitOps

GitOps — это операционный подход, при котором Git является единственным источником истины для инфраструктуры и приложений.

**Принципы:**
1. Декларативное описание всего
2. Версионирование в Git
3. Автоматическая синхронизация
4. Контроль через Pull Requests

**Инструменты:**
- ArgoCD — для Kubernetes
- Flux — альтернатива ArgoCD

## Безопасность в DevOps (DevSecOps)

### Shift Left Security
Интеграция проверок безопасности на ранних этапах CI/CD.

### Инструменты:
- **SAST**: Статический анализ кода (SonarQube, Snyk)
- **DAST**: Динамическое тестирование (OWASP ZAP)
- **Dependency Scanning**: Проверка зависимостей (Dependabot)
- **Container Scanning**: Проверка образов (Trivy)

## Заключение

DevOps и CI/CD — это не просто инструменты, а культурный сдвиг в организации разработки. Автоматизация, измерение и непрерывное улучшение позволяют командам доставлять качественное ПО быстрее и надёжнее.
