# NoSQL базы данных

## Введение в NoSQL

NoSQL (Not Only SQL) — это класс систем управления базами данных, которые отличаются от традиционных реляционных СУБД. Они разработаны для работы с большими объёмами данных, горизонтального масштабирования и гибких схем данных.

## Типы NoSQL баз данных

### Документные базы данных

Хранят данные в виде документов (обычно JSON или BSON). Каждый документ может иметь свою структуру.

**MongoDB:**
MongoDB — самая популярная документная база данных. Предоставляет гибкую схему, мощный язык запросов и горизонтальное масштабирование.

**Ключевые особенности MongoDB:**
- Гибкая схема документов
- Богатый язык запросов с агрегациями
- Индексация любых полей
- Репликация и шардинг
- GridFS для хранения файлов

**Когда использовать MongoDB:**
- Каталоги продуктов с разными атрибутами
- Системы управления контентом
- Приложения с быстро меняющимися требованиями
- Хранение JSON-данных

### Key-Value хранилища

Простейший тип NoSQL — хранят пары ключ-значение. Обеспечивают очень быстрый доступ по ключу.

**Redis:**
Redis (Remote Dictionary Server) — это высокопроизводительное in-memory хранилище данных. Поддерживает различные структуры данных.

**Структуры данных Redis:**
- Strings — простые значения
- Lists — списки строк
- Sets — неупорядоченные множества
- Sorted Sets — упорядоченные множества с весами
- Hashes — словари
- Streams — журналы событий

**Применение Redis:**
- **Кэширование**: Самое частое применение. Redis хранит данные в памяти, обеспечивая микросекундное время отклика
- **Сессии пользователей**: Хранение данных сессий
- **Очереди сообщений**: Простые очереди через списки
- **Лидерборды**: Sorted Sets идеальны для рейтингов
- **Rate Limiting**: Ограничение частоты запросов
- **Pub/Sub**: Публикация и подписка на сообщения

**Производительность Redis:**
Redis способен обрабатывать более 100,000 операций в секунду на обычном сервере. Данные хранятся в оперативной памяти, что обеспечивает минимальную задержку.

**Персистентность Redis:**
- **RDB (Redis Database)**: Периодические снимки
- **AOF (Append Only File)**: Журнал всех операций
- Комбинация обоих для максимальной надёжности

### Колоночные базы данных

Хранят данные по столбцам, а не по строкам. Оптимальны для аналитических запросов.

**Apache Cassandra:**
Распределённая база данных для обработки больших объёмов данных с высокой доступностью.

**Особенности Cassandra:**
- Нет единой точки отказа
- Линейное масштабирование
- Tunable consistency
- CQL (Cassandra Query Language)

**ClickHouse:**
Колоночная СУБД для онлайн-аналитики (OLAP) от Яндекса.

**Особенности ClickHouse:**
- Сверхбыстрая аналитика
- Сжатие данных
- Векторные вычисления
- SQL-совместимость

### Графовые базы данных

Хранят данные в виде узлов и связей между ними. Оптимальны для работы с сильно связанными данными.

**Neo4j:**
Самая популярная графовая база данных. Использует язык запросов Cypher.

**Применение Neo4j:**
- Социальные сети
- Рекомендательные системы
- Fraud detection
- Knowledge graphs

## Сравнение SQL и NoSQL

| Критерий | SQL | NoSQL |
|----------|-----|-------|
| Схема | Фиксированная | Гибкая |
| Масштабирование | Вертикальное | Горизонтальное |
| Согласованность | Строгая (ACID) | Eventual (BASE) |
| Запросы | SQL | Разные API |
| Связи | JOIN | Денормализация |

## CAP-теорема

CAP-теорема утверждает, что распределённая система может обеспечить только два из трёх свойств:

- **Consistency (Согласованность)**: Все узлы видят одинаковые данные
- **Availability (Доступность)**: Каждый запрос получает ответ
- **Partition Tolerance (Устойчивость к разделению)**: Система работает при сетевых разрывах

**Выбор систем:**
- **CP (Consistency + Partition Tolerance)**: MongoDB, Redis Cluster
- **AP (Availability + Partition Tolerance)**: Cassandra, CouchDB
- **CA (Consistency + Availability)**: Традиционные RDBMS (не распределённые)

## Когда использовать NoSQL

**Подходит для:**
- Большие объёмы неструктурированных данных
- Горизонтальное масштабирование
- Быстрая разработка с меняющейся схемой
- Специфические паттерны доступа (графы, временные ряды)
- Кэширование и сессии (Redis)

**Не подходит для:**
- Сложные транзакции между сущностями
- Строгая согласованность данных
- Сложные аналитические запросы (JOIN)
- Регулируемые отрасли с требованиями ACID

## Гибридный подход

Многие современные приложения используют комбинацию баз данных:

1. **PostgreSQL** — основное хранилище с транзакциями
2. **Redis** — кэширование и сессии
3. **Elasticsearch** — полнотекстовый поиск
4. **ClickHouse** — аналитика

Этот подход называется "Polyglot Persistence" и позволяет использовать лучшие инструменты для каждой задачи.

## Заключение

NoSQL базы данных — это не замена реляционным СУБД, а дополнение к ним. Выбор типа базы данных должен основываться на конкретных требованиях: структуре данных, паттернах доступа, требованиях к масштабированию и согласованности.
